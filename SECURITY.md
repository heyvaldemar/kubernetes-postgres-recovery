# Security policy

## Supported versions

| Version | Supported |
|---|---|
| The latest release | yes |
| `main` | yes |
| Older releases | no |

## Reporting a vulnerability

Report privately through GitHub: **Security → Report a vulnerability** on this repository. Email to v@valdemar.ai also works. The process is described at [heyvaldemar.com/security](https://heyvaldemar.com/security/).

You can expect an acknowledgment within 7 days. There is no bounty program; valid, responsibly disclosed reports are credited in the changelog. Please do not open public issues for security reports.

## What this repository is

A reference, not a hosted service. A vulnerability here is most likely a default that loses data the README says it keeps, or that lets backups be read or deleted more easily than the threat model says.

## Supply chain

- Container images are pinned by digest, in the manifests and in what the charts render, and CI fails on one that is not.
- GitHub Actions are pinned by commit SHA; CLI tools by version and sha256 (`tools.lock`); CI images by digest (`ci-images.pins`).
- Each release carries a `git archive` of the tag, a keyless Cosign signature over it and SLSA provenance, made by GitHub Actions with a short-lived identity and no stored key.

## Credentials

None stored. The S3 keys for the bucket are generated by `scripts/install.sh` at install time and exist only in the cluster; the database's passwords are generated by CloudNativePG in the cluster.
